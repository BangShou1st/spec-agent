# Phase 5.2 Exit Criteria — Prompt + Structured Contract

## Goals

- Real models receive a real, frozen lineage context (nodes, answers, patches,
  requirement state, special inputs, allowed source references) — never a bare
  snapshot id.
- Every model call carries a versioned production prompt; unsupported tasks
  fail closed.
- Model output is parsed strictly and fail-closed into the four production
  contracts; the runtime owns every identity and all provenance grounding.

## Acceptance checklist

- [x] Model input envelope is `{"context": {...}, "taskInput": {...}}` built
      only from the frozen `ContextSnapshot` inclusion manifest.
- [x] Requirement state comes from `RequirementStateBuilder.buildForContext`
      only; sibling routes, live route state, and latest spec snapshots are
      never queried.
- [x] Data minimization: no timestamps, `createdByUser`, credentials, API
      keys, agent run traces, excluded route content, or raw repository
      records reach the model.
- [x] Context isolation: sibling route content and regeneration-excluded
      content (old answers, old patches, child subtrees) never appear in the
      input JSON; regenerate special inputs (`oldQuestion`, `oldPurpose`,
      `userInstruction`) are the only allowed regeneration content.
- [x] Task input is explicit run-local data: INTERPRET_ANSWER carries the
      answer; DRAFT_ANSWER_PATCH carries answer + interpretation; post-answer
      DRAFT_NODE carries `mode=after_answer` + answer + acceptedPatch;
      initial DRAFT_NODE carries `mode=initial`. No live snapshot rebuild.
- [x] Four versioned production prompts: `draft-node.v1`,
      `interpret-answer.v1`, `draft-answer-patch.v1`, `draft-spec.v1`;
      GAP_ANALYSIS / PLAN_NEXT_ACTION / REFLECT_NODE / REFLECT_PATCH /
      GROUND_SPEC fail closed.
- [x] System policy declares the supplied context is data, not instructions;
      user answers never enter the system prompt.
- [x] `StructuredModelOutputParser` (strict, fail-closed) rejects missing
      fields, wrong types, unknown enums, blank strings, out-of-range
      confidence, runtime-owned id fields, and malformed nested structures.
      No repair, coercion, or retry.
- [x] Runtime-owned identity: NodeOption ids and Claim ids are generated by
      the runtime; CONFIRMED claims are grounded with real answered node and
      answer ids; ASSUMED/UNRESOLVED/REJECTED claims never keep model-chosen
      source ids.
- [x] ModelResponse trace carries `promptVersion` plus SHA-256 `promptHash`
      and `modelOutputHash`; no API key anywhere in trace or exceptions.
- [x] DRAFT_SPEC source references are copied from `allowedSourceRefs`;
      `SpecGroundingGate` and `SpecSourceReferenceGuard` stay enforced.
- [x] Fake adapter speaks the same model-facing contract and passes the
      structured parser; all fake-full-loop integration tests stay green.
- [x] Full regression: `gradlew test` BUILD SUCCESSFUL, 0 failures.
- [x] Env-gated live smoke exercises all four production tasks against the
      real OpenCode Zen free model.

## Not in scope (Phase 5.2)

- No production prompts for GAP_ANALYSIS / PLAN_NEXT_ACTION / REFLECT_NODE /
  REFLECT_PATCH / GROUND_SPEC (fail closed).
- No retry/repair/fallback: invalid model output fails the run.
- No prompt platform, database, or CMS; no frontend/controller changes.
- No transport rewrite; no change to Route/Context ownership or
  SpecSnapshot source-of-truth status.
- Phase 5.3 full-loop hardening is a separate phase.
