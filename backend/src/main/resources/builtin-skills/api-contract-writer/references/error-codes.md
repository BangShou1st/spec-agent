# 错误码登记表

新增错误码时同步在此登记；同一语义不得使用两个 code。
`可重试` 一栏决定调用方能否自动重试——写错会导致重复写入或永久卡死。

| code | HTTP | 含义 | 可重试 |
| --- | --- | --- | --- |
| `VALIDATION_ERROR` | 400 | 请求参数缺失或不合法 | 否 |
| `UNKNOWN_FIELD` | 400 | 请求包含契约未定义的字段 | 否 |
| `UNAUTHORIZED` | 401 | 缺少或错误的凭据 | 否 |
| `FORBIDDEN` | 403 | 凭据有效但无权执行该操作 | 否 |
| `NOT_FOUND` | 404 | 目标资源不存在 | 否 |
| `CONFLICT` | 409 | 与当前资源状态冲突（如重复的唯一键） | 否 |
| `VERSION_MISMATCH` | 409 | 基于过期的版本号提交 | 是（先重新读取） |
| `NOT_CONFIGURED` | 409 | 依赖的配置尚未完成（如模型 Provider 未配置） | 否 |
| `UPSTREAM_UNAVAILABLE` | 502 | 上游服务不可达 | 是（有界重试） |
| `UPSTREAM_REJECTED` | 502 | 上游明确拒绝了请求内容 | 否 |
| `TIMEOUT` | 504 | 上游超时 | 是（有界重试） |
| `INTERNAL_ERROR` | 500 | 未预期的服务端错误 | 否（需排查） |

## 判定原则

1. **「业务上不允许」不是 500。** 用 4xx，并给出可操作的 code。
2. **必须区分「重试有用」与「重试无用」。** 把不可重试的失败标成可重试，
   会造成重复写入；把可重试的标成不可重试，会让系统卡在无人工干预无法恢复的状态。
3. **错误信息要能定位原因。** 不要把多种不同原因压成同一个 code
   （例如「上游失败」同时覆盖「不可达」和「内容被拒」）。
4. **不得回显敏感值。** 错误信息与日志中都不得出现完整密钥或令牌。
