## 一、资产 A (原 68 条) 关键争议条目决策表

### 1. A001 / A003：核心预期来源与替代相关来源
- **A001 原文**：“这个问题被两个分支共用，回答以后是不是只认同一个 Answer？”
  - **候选标签**：`F00` ("同一共享 Question 在项目内至多有一个不可变 Answer 身份...")
  - **允许的替代相关来源**：`F02` (重答创建新 Question 身份), `F03` (路线分叉保留共享祖先节点身份)
  - **建议处理方式**：主预期记为 `F00`；若 Top-8 同时召回 `F02` 或 `F03` 视为良性相关背景（Tolerated Context），不扣分；首相关 MRR 优先考量 `F00`。
  - **理由**：分支共用、不可变答案与分叉祖先在 Graph Model V2 中互为关联概念，检索捞出关联规则符合语义相似度。
  - **人类决策选项**：
    - [ ] **采纳 AI 建议**：F00 为主，F02/F03 设为次级容忍相关。
    - [ ] **严格模式**：仅认 F00 为唯一合法，返回 F02/F03 视为噪声。

- **A003 原文**：“刚确认的答案要重答，是不是得另建问题而不是覆盖旧记录？”
  - **候选标签**：`F02` ("不可变 Answer 不原地修改；重新回答创建新的规范 Question 身份，历史继续保留。")
  - **允许的替代相关来源**：`F00`
  - **建议处理方式**：主预期保持 `F02`；允许 `F00` 作为次级相关不扣分。
  - **理由**：重答与不可变 Answer 属于因果互补事实。
  - **人类决策选项**：
    - [ ] **采纳 AI 建议**：F02 为主，允许 F00 次级容忍。
    - [ ] **严格模式**：仅认 F02。

### 2. A010 / A011：安全保障与异常恢复交叉来源
- **A010 原文**：“本地检索服务断了，项目 Agent 本轮必需的路线事实还在吗？”
  - **候选标签**：`F09` ("项目必需上下文由 Runtime 保证；补充检索失败不能丢失当前路线的规范事实。")
  - **允许的替代相关来源**：`F14` ("项目首次补充检索结果或失败状态随输入冻结，历史回放不重新搜索。")
  - **建议处理方式**：唯一主预期保持 `F09`，`F14` 仅作参考。
  - **理由**：直问运行时上下文保障，F09 已完全覆盖。
  - **人类决策选项**：
    - [ ] **采纳 AI 建议**：仅认 F09 为主相关。
    - [ ] **双来源模式**：允许 F09 或 F14 任一命中。

- **A011 原文**：“写操作结果没有确认，恢复进程会不会再执行一次？”
  - **候选标签**：`F10` ("未知结果 UNKNOWN 的工具不自动重放或通过换 callId 重试副作用。")
  - **允许的替代相关来源**：`F15` ("正在执行的 run 在重启后按阶段一中断终止；新请求可读取最后完成的 checkpoint 边界。")
  - **建议处理方式**：主预期为 `F10`，次级容忍来源设为 `F15`。
  - **理由**：F10 专指 UNKNOWN 副作用操作防重复，F15 属于系统级重启终止，F10 更贴切。
  - **人类决策选项**：
    - [ ] **采纳 AI 建议**：F10 为主，F15 次级容忍。
    - [ ] **严格模式**：仅认 F10。

### 3. A041 – A048：多来源 All-of 覆盖必要性裁决
- **涉及条目**：
  - A041: 共享问题唯一答案与重答规则 (`F00, F02`)
  - A042: Focus 不切路线与语义边不充当探索箭头 (`F04, F05`)
  - A043: 检索故障不丢事实与历史输入不重检索 (`F09, F14`)
  - A044: 重启中断旧 run 与 UNKNOWN 写不重放 (`F15, F10`)
  - A045: 引用位置保留与撤回准入生效阶段 (`R00, F07` - 跨类型)
  - A046: Python 存储连接与新代际激活条件 (`R01, R02` - 双资源)
  - A047: Skill 暂存不启用与模型不能临时扩权 (`F11, F08`)
  - A048: 正文不显协议参数与历史刷新不重放导航 (`F13, F12`)
- **建议处理方式**：维持严格 `all-of` 标准，必须两个来源同时出现在 Top-8 结果中才记为覆盖（1 分），否则记为 0 分。验收门槛设为 ≥ 6/8 (75%)。
- **理由**：多事实合成查询旨在检验 RRF 混合排名的多峰召回能力，单靠命中一个来源无法支撑下游 Agent 完整回答。
- **人类决策选项**：
  - [ ] **批准严格 all-of 标准**（建议）：门槛设为 ≥ 6/8。
  - [ ] **松弛为任意命中 (Any-hit)**：任一命中即算通过（不推荐，会降低多事实召回考核效力）。

### 4. A049 – A056：近主题无答案与答案充分性区别（核心方法论决策）
- **核心现象**：
  - A049 问“Answer 历史保留多少年”，语料有保留事实但无年限数字。
  - A050 问“Focus 切换最多每秒点几次”，语料有切换规则但无频控数字。
  - A051 问“参考资源可以上传多少个文件”，语料有分块规则但无文件上限。
  - A052~A056 同样询问了语料中不存在的具体配额/时限/负责人。
- **建议处理方式**：**将 NEAR_NO_ANSWER 8 条正式剥离为“独立检索诊断类别”，不列入检索零命中硬性淘汰门槛**。
- **理由**：
  1. 检索层任务是召回语义相关候选。当用户询问“Answer 历史保留多少年”时，检索出有关 Answer 历史保留的条款属于语义相似度正确。
  2. 识别“语料不足以回答具体年限”是下游生成/判定 Agent 的责任，而非检索引擎强制零召回的职责。
  3. 若强求向量检索在相似度很高时不返回，会导致实际业务中正常相关问题被误杀。
- **人类决策选项**：
  - [ ] **批准分离为诊断项**（推荐）：单独统计“主题片段召回率”与“严格零命中率”，不设硬性淘汰分。
  - [ ] **维持严格 Zero-hit**：强制要求 8 条检索结果必须全部为空（不推荐，可能导致检索引擎负优化）。

### 5. A057 – A064：撤回版本与权限隔离零泄漏（安全红线）
- **涉及条目**：
  - A057~A060: 撤回标识符 OBS-OLD-0~3，禁止返回 `S00~S03`。
  - A061~A064: 跨项目隔离标识符 AUDIT-RESTRICT-0~3，禁止返回 `P00~P03`。
- **建议处理方式**：**保持绝对 0 容忍（零泄漏闸门 = 0）**。一旦发生任何泄漏，直接判定验收 FAIL。
- **人类决策选项**：
  - [ ] **批准 0 泄漏红线**：泄漏数必须恒等于 0。

### 6. A065 – A068：完全无关负样本零命中目标
- **涉及条目**：A065~A068（高铁餐补、微服务副本、退款审批、采购保密期）。
- **建议处理方式**：**保持 100% 零命中（4/4）**。由于与项目需求和架构毫无关联，向量距离应均 > 0.50，词法无匹配。
- **人类决策选项**：
  - [ ] **批准 100% 零命中门槛**：4 条必须全部返回空。
